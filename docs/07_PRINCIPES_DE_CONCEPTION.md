# SikaGlé

## Principes de Conception

**Version :** 1.0

**Statut :** Officiel

**Dernière mise à jour :** Juillet 2026

---

# Préambule

Les principes de conception définissent la manière dont SikaGlé est imaginé, développé et amélioré.

Ils constituent la référence pour toutes les décisions techniques, fonctionnelles et stratégiques.

Lorsqu'une décision est difficile à prendre, ces principes doivent primer sur les préférences individuelles.

Ils garantissent que SikaGlé reste fidèle à sa mission, quelles que soient les évolutions futures du projet.

---

# Principe 1 — L'utilisateur avant la technologie

La technologie est un moyen.

Elle n'est jamais une finalité.

Nous ne développons pas une fonctionnalité parce qu'elle est innovante.

Nous la développons parce qu'elle résout un problème réel.

Avant toute nouvelle fonctionnalité, nous devons répondre à la question suivante :

> Quel problème concret de l'utilisateur cette fonctionnalité résout-elle ?

Si aucun problème n'est identifié, la fonctionnalité est reportée.

---

# Principe 2 — Les cinq personas guident le produit

Toutes les fonctionnalités doivent apporter de la valeur à au moins un des cinq personas officiels.

- Coffi
- Aïcha
- Rodrigue
- Institution
- Entrepreneur Agricole

Chaque développement doit clairement identifier :

- le persona concerné ;
- le besoin traité ;
- la valeur créée.

---

# Principe 3 — Comprendre avant de répondre

SikaGlé ne répond jamais immédiatement.

Avant toute réponse, le système cherche à comprendre :

- la culture concernée ;
- les symptômes ;
- le contexte ;
- les actions déjà réalisées ;
- les informations manquantes.

Une réponse rapide mais incorrecte est moins utile qu'une réponse légèrement plus lente mais pertinente.

---

# Principe 4 — Raisonner avant de conclure

Le moteur ne doit jamais produire une conclusion sans raisonnement.

Chaque réponse doit être précédée par :

- une analyse ;
- plusieurs hypothèses lorsque nécessaire ;
- une recherche documentaire ;
- une prise en compte du contexte.

L'objectif est d'accompagner une décision, pas de produire une réponse automatique.

---

# Principe 5 — Les connaissances avant les opinions

Les recommandations de SikaGlé reposent sur des connaissances vérifiées.

Les principales sources sont :

- publications scientifiques ;
- guides techniques ;
- documents institutionnels ;
- recherches validées.

Lorsque cela est possible, les réponses doivent citer leurs sources.

---

# Principe 6 — Le contexte est essentiel

Un même symptôme peut avoir plusieurs causes.

Les recommandations doivent tenir compte de :

- la culture ;
- la saison ;
- la météo ;
- la localisation ;
- les traitements déjà appliqués ;
- les informations fournies par l'utilisateur.

Une réponse sans contexte est une réponse incomplète.

---

# Principe 7 — La simplicité est une qualité

Une réponse simple est souvent meilleure qu'une réponse complexe.

Le niveau de détail doit être adapté au profil de l'utilisateur.

Exemple :

Coffi recevra une explication simple.

Rodrigue pourra recevoir des références scientifiques détaillées.

Le système adapte son langage sans modifier le fond de la recommandation.

---

# Principe 8 — L'accessibilité est une exigence

SikaGlé doit être utilisable par tous.

Le produit doit fonctionner :

- avec des smartphones d'entrée de gamme ;
- sur des réseaux mobiles limités ;
- avec des utilisateurs peu familiers du numérique.

Les langues locales sont considérées comme une priorité.

---

# Principe 9 — La confiance se mérite

La confiance des utilisateurs est le principal capital de SikaGlé.

Pour la préserver :

- aucune réponse ne doit être inventée ;
- les incertitudes doivent être reconnues ;
- les limites du système doivent être expliquées.

Lorsque le système ne sait pas, il doit le dire.

---

# Principe 10 — Les données appartiennent aux utilisateurs

Les données personnelles restent la propriété des utilisateurs.

SikaGlé s'engage à :

- protéger les informations personnelles ;
- limiter leur collecte ;
- anonymiser les observations utilisées pour les analyses.

Les données individuelles ne sont jamais vendues.

---

# Principe 11 — Les observations servent le bien commun

Chaque interaction peut produire une observation anonyme.

Ces observations permettent :

- d'améliorer les diagnostics ;
- de détecter des tendances ;
- d'aider les institutions ;
- de renforcer les systèmes d'alerte.

Aucune analyse ne doit permettre d'identifier une personne.

---

# Principe 12 — Une architecture évolutive

L'architecture doit permettre :

- l'ajout de nouvelles cultures ;
- l'ajout de nouvelles langues ;
- l'intégration de nouveaux modèles d'IA ;
- l'ouverture vers d'autres pays.

Le développement doit éviter les dépendances inutiles.

---

# Principe 13 — Chaque module a une responsabilité

Chaque composant logiciel doit avoir une responsabilité clairement définie.

Les responsabilités ne doivent pas se chevaucher.

Cette séparation garantit :

- une meilleure maintenance ;
- une meilleure qualité ;
- une meilleure évolutivité.

---

# Principe 14 — La qualité avant la quantité

Ajouter des fonctionnalités n'est pas un objectif.

Une fonctionnalité utile vaut mieux que dix fonctionnalités peu utilisées.

Nous privilégions :

- la stabilité ;
- la fiabilité ;
- la simplicité.

---

# Principe 15 — L'amélioration continue

Le produit évolue grâce :

- aux retours des utilisateurs ;
- aux observations terrain ;
- aux nouvelles connaissances scientifiques ;
- aux évolutions technologiques.

Chaque version doit améliorer la précédente.

---

# Principe 16 — La transparence

Les utilisateurs doivent comprendre :

- pourquoi une recommandation est proposée ;
- quelles informations ont été utilisées ;
- quelles sont les limites de cette recommandation.

Une IA de confiance est une IA explicable.

---

# Principe 17 — L'impact avant les revenus

Les revenus assurent la pérennité du projet.

Ils ne doivent jamais devenir l'objectif principal.

Une décision commerciale ne doit jamais diminuer :

- la qualité des conseils ;
- l'accessibilité du produit ;
- la confiance des utilisateurs.

---

# Principe 18 — Construire pour durer

Toutes les décisions doivent être prises avec une vision à long terme.

Nous privilégions :

- une architecture solide ;
- une documentation complète ;
- des standards de qualité élevés.

Le coût d'une bonne conception est toujours inférieur au coût d'une reconstruction.

---

# Les questions de validation

Avant d'accepter une nouvelle fonctionnalité, nous répondons systématiquement aux questions suivantes :

1. Quel persona est concerné ?

2. Quel problème résout cette fonctionnalité ?

3. Apporte-t-elle une réelle valeur ?

4. Est-elle cohérente avec notre mission ?

5. Respecte-t-elle nos principes ?

6. Est-elle maintenable ?

7. Peut-elle évoluer dans le temps ?

Si une réponse est négative, la fonctionnalité doit être repensée.

---

# Notre engagement

Nous développons SikaGlé avec une conviction simple :

La technologie doit servir les personnes.

Chaque ligne de code doit rapprocher les connaissances agricoles des femmes et des hommes qui en ont besoin.

Nous refusons de développer des fonctionnalités uniquement parce qu'elles sont techniquement intéressantes.

Nous développons uniquement ce qui améliore réellement la vie de nos utilisateurs.

---

# Notre devise

> **Nous ne développons pas des fonctionnalités.**

> **Nous résolvons les problèmes des agriculteurs.**

---

# Conclusion

Les principes de conception sont le fondement de toutes les décisions prises dans le projet SikaGlé.

Ils garantissent que le produit restera fidèle à sa mission, quel que soit son niveau de croissance.

Ils constituent la référence commune de toutes les personnes qui participeront au développement de SikaGlé aujourd'hui et demain.
